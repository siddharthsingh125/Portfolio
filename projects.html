A/B Testing | Automotive / PLP

PLP Content to Tab Navigation

Redesigning vertically stacked content into an intuitive tabbed navigation experience.

Test Type Navigation A/B Test
Market / Platform Automotive / PLP
Device Mobile & Desktop
Primary Goal Content Discoverability

Challenge

The existing PLP contained multiple content sections stacked vertically, creating a longer page experience and requiring users to scroll through large amounts of supporting content to locate relevant information.

Hypothesis

By converting the existing vertically stacked content sections into clearly structured tabs, we can reduce unnecessary scrolling, improve content discoverability, and create a cleaner PLP experience.

Control vs Variant

Control

Existing Vertically Stacked Content

All PLP supporting content sections stacked linearly down the page, resulting in extensive scroll depth and hidden key product specs.

Variant

Tabbed Content Navigation

Streamlined tabbed interface organizing content into easily switchable tabs, drastically shortening page height while keeping all data accessible.

CRO Approach

  • Reviewed the existing PLP content structure.
  • Identified opportunities to reduce vertical scrolling.
  • Converted existing content sections into tabs.
  • Preserved existing content while improving its presentation.
  • Focused on navigation clarity and reduced user friction.
  • Considered responsive behavior across desktop and mobile.
  • Prepared the experience for A/B testing and behavioral analysis.

Key Changes

  • Replaced tall multi-tier sections with compact tab headers.
  • Implemented smooth tab transition animations.
  • Optimized touch-friendly tab targets on mobile devices.
  • Enhanced visual hierarchy for specification tables.

Implementation

  • Built with accessible semantic HTML and ARIA tabs.
  • Lightweight JavaScript tab switching logic.
  • Responsive CSS with horizontal scroll on mobile.
  • Validated through cross-browser and QA testing.

Key Metrics & KPIs

Tab Interaction Rate Content Engagement Scroll Depth PLP Engagement Product Interactions Session Engagement Conversion Rate

Impact / Learning

The experiment provides measurable insight into whether reorganizing lengthy automotive PLP content into a clean tabbed navigation reduces scroll fatigue, improves user interaction with critical product specifications, and facilitates smoother transition toward product inquiries and conversions.

Running in Main Navigation — Retest

Test 12.01.01 — Evaluating primary navigation category placement for category discoverability.

Test Name Test 12.01.01
Market Australia (AU)
Devices Mobile & Desktop
Primary Goal Category Discoverability

Challenge

The experiment focused on improving product discoverability by evaluating whether adding “Running” directly to the main navigation could make the category easier to find and reduce the number of steps required for users to reach relevant products. A previous version had been conducted, and this experiment was planned as a retest using the updated navigation design.

Hypothesis

By introducing “Running” as a dedicated item in the main navigation, users interested in running products will be able to discover the category more easily, potentially improving navigation engagement and progression into the relevant product journey.

Control vs Variant

Control

Existing Main Navigation

Standard navigation bar without a dedicated top-level "Running" link, requiring multi-level subcategory clicks.

Variant

Main Navigation with “Running” Added

Updated navigation featuring a prominent top-level "Running" category item across desktop headers and mobile navigation drawers.

CRO Approach

  • Reviewed the existing navigation structure.
  • Identified product-category discoverability as an optimization opportunity.
  • Evaluated the impact of adding “Running” directly to the primary navigation.
  • Considered both mobile and desktop navigation behavior.
  • Retested the concept using the updated navigation design.
  • Focused on reducing navigation friction and improving category discoverability.
  • Ensured the implementation remained consistent with the existing navigation system.

Key Changes

  • Injected "Running" item into top-level navigation list.
  • Optimized spacing and alignment across header container.
  • Added direct link inside mobile drawer accordion.
  • Retained active visual hover states and dropdowns.

Implementation

  • Clean DOM injection via client-side testing engine.
  • Preserved native event listeners and sub-menu triggers.
  • Zero layout shift (CLS) during navigation rendering.
  • Cross-device manual QA testing across AU viewports.

Key Metrics & KPIs

Main Navigation Interaction Rate “Running” Navigation Clicks Category Click-Through Rate (CTR) Product Listing Page (PLP) Visits User Journey Progression Engagement Rate Conversion Rate

Impact / Learning

The experiment provides measurable insight into whether placing a high-value category directly in the main navigation improves product discoverability and user progression, informing long-term navigation architecture decisions.

Mobile Buybox & Product Purchase UX

SCH | SM07 — Restructuring the mobile purchase area for seamless add-to-cart progression.

Test ID SCH | SM07
Platform Shopware E-Commerce
Device Mobile Focused
Primary Goal Add-to-Cart Progression

Challenge

The existing mobile purchase area presented an opportunity to improve the way important purchase information was structured. Product information, variants, delivery details, quantity selection, and the primary purchase CTA needed to be organized into a clearer hierarchy without changing existing shopping functionality.

Hypothesis

By restructuring the mobile purchase area and creating a clearer buybox hierarchy, we can reduce purchase friction, improve product-selection usability, make delivery information easier to understand, and encourage users to proceed toward add-to-cart.

Control vs Variant

Control

Existing Mobile Purchase Area

Scattered product title, standard dropdown variant selectors, isolated delivery status, and detached CTA buttons.

Variant

Redesigned Unified Buybox

Clear product header, ratings, visual image-based color swatches, improved size selection, prominent price, dedicated delivery block, quantity + CTA row, and consultation card.

CRO Approach

  • Product Selection: Improved color-selection visibility; displayed product images with color names; limited initial options to reduce visual overload; added expandable option for additional colors.
  • Size Selection: Increased size-button usability for mobile users; created clearer active and inactive states.
  • Buybox Hierarchy: Established a stronger information hierarchy; made price immediately visible; moved delivery information into a dedicated status block; combined quantity selection and CTA into a single purchase row.
  • Trust & Support: Added shipping, payment, and return information; introduced a consultation section for users needing help with sizing.

Implementation & Shopware Architecture

The experiment required extensive frontend restructuring and restyling while preserving existing Shopware core functionality. Dynamic shop values—including product price, delivery information, stock availability, product variants, quantity, and add-to-cart API logic—remained connected to the existing backend without hardcoding.

Key Metrics & KPIs

Add-to-Cart Rate Product Variant Interaction Color Selection Interaction Size Selection Interaction Buybox Engagement CTA Click-Through Rate Quantity Selector Interaction Delivery Info Engagement Purchase Conversion Rate

Impact / Learning

The experiment was designed to create a clearer mobile purchase experience by placing critical decision-making information closer together and eliminating friction between: Product Selection → Purchase Information → Add to Cart.

Cart Page Upsell Module Optimization

A Conversion Rate Optimization case study delivering Average Order Value growth.

Challenge

The cart page offered no opportunity to promote complementary products before checkout, limiting the potential to increase Average Order Value (AOV). The goal was to introduce relevant upsell options without disrupting the customer's purchase journey or creating unnecessary friction.

Solution

We designed a lightweight upsell module featuring two optional accessories—Chain Extender and Gift Box. Customers could add either item with a single click directly from the cart page, while those who chose not to engage experienced no changes to their cart, ensuring a seamless checkout flow.

Our Approach

We began by reviewing the client's hypothesis and understanding the desired business outcome. After analyzing the existing cart experience, we identified the ideal placement for the upsell component and validated product eligibility with the client. The solution was implemented using a clean, non-intrusive interface that aligned with the existing design system. Finally, comprehensive Manual QA and Cross-Browser Testing ensured reliable functionality before deployment.

Key Features & Implementation

  • Introduced two optional cart-page upsell products.
  • One-click opt-in functionality for a frictionless experience.
  • Automatic cart update when an upsell is selected.
  • Cart total remains unchanged if no option is selected.
  • Responsive implementation across desktop, tablet, and mobile.
  • Cross-browser compatibility testing.
  • Manual QA testing to validate cart behavior.
  • Maintained consistent UI with the existing checkout experience.

Impact Delivered

The implementation provided a scalable upsell framework that supports future CRO initiatives while preserving a smooth checkout experience. The experiment was designed to encourage higher Average Order Value, improve upsell adoption, and generate measurable insights through A/B Testing without introducing unnecessary user friction.

Sliding Mini Cart Redesign & Checkout

Interactive sliding cart development bypassing API limitations to boost checkout flow.

Challenge

The existing notification-style mini cart had several technical limitations that made redesigning it impractical. It displayed only one product at a time, lacked quantity controls, and exposed limited product information, making it difficult to implement the new design while preserving existing functionality.

Solution

Instead of heavily modifying the existing component, a completely new sliding mini cart was developed. Product data was fetched using the existing cart APIs and rendered inside the new interface, allowing multiple cart items, quantity management, product removal, dynamic pricing, and a modern checkout experience without disrupting the backend cart logic.

Our Approach

After reviewing the existing cart architecture, we identified that extending the original mini cart would introduce unnecessary complexity due to its DOM structure and limited functionality. We collaborated with the client to confirm expected behavior, then built a reusable sliding cart component that consumed the existing cart API. The new component maintained synchronization with the backend while providing a significantly improved user experience through responsive interactions and optimized UI.

Key Features & Implementation

  • Built a custom sliding mini cart from scratch.
  • Integrated existing cart APIs to fetch live cart data dynamically.
  • Displayed multiple products simultaneously.
  • Implemented quantity increase and decrease functionality.
  • Added product removal capability directly in the drawer.
  • Supported dynamic pricing including discounted products.
  • Displayed sale and original prices side-by-side when applicable.
  • Added a prominent Checkout Call to Action.
  • Responsive layout optimized for desktop and mobile viewports.
  • Smooth open and close cart drawer animations.

Impact Delivered

The redesigned sliding cart created a more intuitive shopping experience by giving customers complete visibility into their cart without interrupting their browsing journey. The implementation reduced interaction friction, simplified cart management, and provided a scalable frontend architecture.
